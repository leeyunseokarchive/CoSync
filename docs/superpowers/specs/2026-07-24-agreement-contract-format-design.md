# Phase 1 — 합의서 양식 계약서화 (Design)

## 배경

CoSync의 최종 산출물인 합의서([app/agreement/document/page.tsx](../../../app/agreement/document/page.tsx))는 현재
표제 → 6개 장(①②③ 조항) → 참여자 목록 → "GENERATED BY COSYNC" 구조다. 실제 계약서가 갖는
전문(preamble)·조 번호 체계·서명란·시행일·분쟁해결·디스클레이머가 없어 "문서"보다 "결과 화면"에
가깝다.

이 문서는 **내용(소프트 운영 합의)은 그대로 두고 출력물의 형식만 계약서처럼 격상**하는 Phase 1을
정의한다. 데이터 모델은 건드리지 않는다.

### 전체 로드맵에서의 위치

풀 비전은 `심층질문 → 전문 합의안 → 별지(주주간계약서 조항 초안)`이며 4단계로 분해했다.

- **Phase 1 — 합의서 양식 계약서화** ← 본 문서. 렌더링/문구만. 독립·즉시 가치. 나머지의 뼈대.
- Phase 2 — 심층 질문 페이지 전문화.
- Phase 3 — 하드 항목(베스팅·leaver·양도제한·경업금지·위약 등) 데이터 수집. 데이터 모델 확장.
- Phase 4 — 별지 = SHA 조항 초안 생성 (Phase 3 의존).

Phase 1의 별지는 **정적 체크리스트**(자리만 잡음)이며, Phase 4에서 이 자리가 조항 초안으로 채워진다.

## 정체성 (설계 원칙)

- 합의서는 **자율적 운영 합의서**다. 법적 계약(주주간계약서)이 아니다.
- 하드 법적 조항(지분·베스팅·tag/drag·경업금지·위약벌)은 Phase 1에서 **생성하지 않는다**. 별지에
  "변호사와 정식 계약서로 다룰 항목"으로 이름만 올린다.
- 문서 어디에도 법적 구속력이 있는 것처럼 오인시키는 표현을 쓰지 않는다. 디스클레이머를 명시한다.

## 변경 범위

**대상 파일:** [app/agreement/document/page.tsx](../../../app/agreement/document/page.tsx) — JSX 렌더링 +
동 파일 내 `<style>` 블록. 그리고 [docs/shareholder-agreement-template-analysis.md](../../shareholder-agreement-template-analysis.md) 갱신.

**건드리지 않는 것:** 데이터 모델, Firestore 스키마, [lib/agreementClauses.ts](../../../lib/agreementClauses.ts)의
조항 텍스트/빌드 로직, [lib/gap.ts](../../../lib/gap.ts). 기존 데이터(팀명, `members[{name, role}]`,
`doc.clauses`, `doc.confirmations`, `doc.version`, `doc.createdAt`, `doc.status`)만 사용한다.

### 1. 전문 (Preamble)

- 위치: `.doc-header` 아래, 첫 `제N조` 위.
- 문구: `본 합의는 {팀명}의 공동창업 구성원인 아래 당사자들이 팀의 운영 원칙과 상호 약속을 정함을 목적으로 한다.`
  - 팀명이 없으면 `본 팀` 으로 대체.
- 당사자 목록: `members` 를 `{name} ({role})` 로 나열. members 가 비면 전문 문단만 출력하고 목록은 생략.
- 작성일: `doc.createdAt` 을 `fmtDate` 로. 없으면 줄 생략.

### 2. 제N장 → 제N조

- 현재: `제{ch.cat + 1}장. {ch.label}`. `groupByChapter` 가 빈 카테고리를 걸러내므로 `cat + 1` 은
  번호를 건너뛸 수 있다(예: cat 2 비면 …제2조 다음 제4조). 
- 변경: `groupByChapter(doc.clauses)` 결과 배열의 **인덱스 기반 순차 번호**로 `제{i + 1}조 ({ch.label})`.
  - 라벨은 그대로(예: "역할 & 책임"). 괄호로 감싸 조 제목 형태로 표기.
- 조항(clauses)은 기존 `①②③…` 항 표기 유지.
- 일반조항 2개(효력·시행 / 분쟁해결)가 이어지므로, 이들의 조 번호는 `본문 조 개수 + 1`, `+ 2` 로
  연속되게 한다.

### 3. 일반조항 (신규 2개 조)

본문 조 뒤에 고정 문구로 append. 조 번호는 위 규칙에 따라 연속.

- `제{N}조 (효력과 시행)`: `본 합의는 구성원 전원이 확정한 날부터 효력을 가지며, 구성원은 매 6개월마다 본 합의를 함께 재점검한다.`
- `제{N+1}조 (분쟁의 해결)`: `본 합의의 해석 또는 이행에 관하여 이견이 발생한 경우, 구성원은 우선 성실히 협의하여 해결한다.`

### 4. 서명란

- 현재 `.doc-parties`(참여자 목록)를 서명란 형태로 교체.
- 각 member: `{name} ({role})` + 서명선 + 확정 상태.
  - `doc.confirmations[m.id]` 있으면 `전자적 동의 {fmtDate}`, 없으면 `미확정`.
- 작성일/시행일 한 줄 추가: `작성일 {fmtDate(doc.createdAt)}`.
- 기존 `doc-confirmed-note`(전원 확정 안내)는 유지.

### 5. 디스클레이머

- 서명란 아래, 별지 위. 눈에 띄되 과하지 않은 주의 박스.
- 문구: `본 문서는 구성원 간 자율적 운영 합의를 정리한 것으로, 법적 계약(주주간계약서 등)을 대체하지 않습니다. 법적 구속력이 필요한 사항은 아래 별지 항목을 변호사와 함께 정식 계약서로 작성하시기 바랍니다.`

### 6. 별지 체크리스트 (정적)

- 문서 최하단. 하드 법적 항목을 정적 목록으로 나열.
- 항목(고정): 지분비율·출자 / 베스팅·클리프 / 주식양도 제한·우선매수권 / Tag-along·Drag-along /
  경업금지·비밀유지 / 위약벌·손해배상 / 이사회 구성·사전동의사항 / 교착 해소·분쟁 관할.
- 마무리 문구: `→ 법적 구속력이 필요한 항목입니다. 변호사와 주주간계약서로 확정하세요.`
- Phase 4에서 이 블록이 조항 초안으로 대체된다. 컴포넌트/섹션 경계를 명확히 두어 교체가 쉽게 한다.

## 인쇄(PDF) 처리

- 새 섹션(전문·일반조항·서명란·디스클레이머·별지)은 모두 `.agreement-doc` 안에 있으므로 기존
  `@media print` 규칙으로 함께 출력된다.
- 별지는 `break-before` 를 주어 새 페이지에서 시작하도록 한다(내용이 밀리면 자연스럽게 넘어가되,
  최소한 별지 제목이 페이지 끝에 걸리지 않게).
- 디스클레이머 박스 배경색은 인쇄 시에도 유지되도록 `print-color-adjust: exact` 를 명시하거나, 배경
  대신 테두리로 표현해 흑백 인쇄에서도 읽히게 한다.

## analysis 문서 갱신

[docs/shareholder-agreement-template-analysis.md](../../shareholder-agreement-template-analysis.md) 를 Phase 1
완료 상태에 맞춰 갱신한다.

- 문서 상단 또는 3장 근처에 **"현재 합의서 양식(Phase 1 반영)"** 을 짧게 기술: 전문·제N조·서명란·
  디스클레이머·별지 구조가 생겼다는 사실.
- 별지(정적 체크리스트)가 문서에 존재하며, Phase 4에서 조항 초안으로 채워질 예정임을 명시.
- 4장("완성도 향상을 위한 보완 필수 정보 목록")이 Phase 3/4의 입력임을 한 줄로 연결.
- 매핑 표 자체(2장·3장 조항 대응)는 사실 관계가 그대로이므로 유지. 형식 변화만 반영한다.

## 비목표 (Non-goals)

- 하드 법적 조항 생성 (Phase 4).
- 심층 질문/데이터 수집 변경 (Phase 2/3).
- 당사자 주민등록번호·주소 등 법적 신원정보 수집 (프리-리걸 유지, 수집하지 않음).
- 데이터 모델·Firestore 스키마 변경.

## 검증

- 확정 합의서(demo-team-b)와 미확정 상태 각각에서 새 섹션이 정상 렌더되는지 화면 확인.
- 서명란 확정/미확정 표기, 빈 members·빈 팀명·createdAt 없음 등 결측 케이스에서 깨지지 않는지 확인.
- `제N조` 번호가 빈 카테고리 존재 시에도 1부터 연속인지 확인.
- PDF 내보내기(window.print) 시 전문·서명란·디스클레이머·별지가 인쇄본에 포함되는지 확인.
