## 1. 목적과 범위

CoSync 서비스 플로우는 `각자 답변 → 팀원 답변과의 갭 비교 → 합의 → 계약서 생성`이다. 이 문서는 그중 **첫 단계인 "각자 답변" 화면의 질문 템플릿**을 정의한다.

조항마다 답변해야 할 값의 성격이 다르다. 금액, 기간, 비율, 사람 지정, 멤버별 배분, 사실 기재가 모두 섞여 있다. 하나의 입력 폼으로는 커버되지 않으므로 **7종 입력 템플릿**을 정의하고, 13개 질문을 각 템플릿에 매핑한다.

**범위에 포함**: 질문 위저드 목업 1개 페이지, 입력 템플릿 7종, 질문 13개, 조항별 정보 카드.
**범위에서 제외**: 갭 비교 화면, 합의 화면, 계약서 생성. Firestore 연동. (모두 별도 작업)

## 2. 확정된 전제

브레인스토밍에서 사용자가 확정한 사항이다.

| 항목 | 결정 | 근거 |
|---|---|---|
| 회사 설립 시점 | **설립 전 기준** | 3조·3의2조·3의3조가 "설립 전 계약" 전용 조문. 설립 전 기준이므로 역할·지분 질문 포함 |
| 답변 단위 | **성격별 분기** | 금액·기간·비율·선택형은 각자 답변 후 합의. 신원 같은 사실정보는 입력만 하고 합의 대상 아님 |
| 팀원 답변 노출 | **블라인드 + 진행률만** | 앵커링 방지. 상단에 "3명 중 2명 응답"만 표시. 기존 온보딩 진단과 동일 |
| 화면 구조 | **위저드 1문항 1화면** | 이전/다음 버튼으로 전환 |
| 위약벌(8조) | **기준금액 1 + 비율 1 → 4개 빈칸 자동 파생** | 빈칸 6개를 개별로 물으면 부담 과다 |
| 추가 후보 질문 | **5개 유지, `제안` 배지 표시** | 신원·주식종류·경업금지·베스팅·매수가격. 기본정보와 관할법원은 이미 정해졌다고 보고 제외 |
| 법률 정보 제공 방식 | **권고 금지, 사실 서술만** | §2-1 참고 |

### 2-1. 법률 정보 제공 원칙 (변호사법)

이 서비스는 특정 값을 권하지 않는다. "위약벌은 1억 원을 권장합니다", "업계 평균은 30%입니다" 같은 문장은 구체적 사안에 대한 법률 판단을 제공하는 것이고, 변호사법 제109조는 변호사가 아닌 자가 보수를 받고 법률사무를 취급하는 것을 금지한다.

반면 조항이 어떻게 작동하는지, 비워두면 어떤 규칙이 적용되는지 설명하는 일반적 법률정보 제공은 이 금지에 해당하지 않는다. 사용자가 스스로 판단할 재료를 주는 것이 서비스의 역할이다.

따라서:

- **금지** — 특정 금액·기간·비율을 권하는 문구, `권장`·`추천`·`통상`·`업계 평균` 같은 단정 표현, 입력값 프리필
- **허용** — 조항의 구조와 작동 방식, 정하지 않았을 때 적용되는 기본 규칙, 값이 낮을 때와 높을 때 각각 따라오는 결과, 법 조문 인용
- **필수** — 정보 카드 하단에 "법률 자문이 아니다"라는 문구를 항상 노출

프리셋 칩(1천만/5천만/1억/3억)은 유지한다. 자릿수를 매번 타이핑하지 않게 하는 입력 단축키이고, 어느 값이 낫다는 표시를 붙이지 않는다.

이 경계는 [lib/contractQuestions.test.ts](../../../lib/contractQuestions.test.ts)의 금지어 테스트가 지킨다. 사용자 노출 문자열에 금지 표현이 들어가면 테스트가 실패한다.

## 3. 입력 템플릿 7종

각 템플릿은 하나의 React 컴포넌트다. 질문 데이터가 `type` 필드로 템플릿을 지정하고, 위저드가 그에 맞는 컴포넌트를 렌더한다.

### 3-1. `amount` — 금액

프리셋 칩 3~4개 + 직접입력. 입력값을 한글 금액으로 병기해 자릿수 오입력을 막는다(`100000000` → `1억 원`).

```
┌────────────────────────────────────────┐
│ [1천만] [5천만] [ 1억 ]● [ 3억 ]        │
│                                        │
│   ₩ [    100,000,000    ]              │
│      1억 원                             │
└────────────────────────────────────────┘
```

- 숫자 입력은 `inputMode="numeric"`, 3자리 콤마 자동 삽입, tabular figures
- 사용처: `decisionAmount`(의사결정 금액 기준), `penalty`(위약벌 기준금액)

### 3-2. `duration` — 기간

단위 칩(일/개월/년)과 값 스테퍼. 베이스 계약서에 이미 값이 적혀 있는 조문은 그 값을 입력 아래 보조 문구로 알린다. 입력란은 비워 둔다 — 채워 넣으면 권고로 읽힌다(§2-1).

```
┌────────────────────────────────────────┐
│ [ 1년 ] [ 3년 ]● [ 5년 ] [ 직접입력 ]      │
│                                        │
│   [ − ]   3   [ + ]  년                 │
│           ⓘ 베이스 계약서에 적힌 값: 5년   │
└────────────────────────────────────────┘
```

- 사용처: `deadlock`(협의 기간), `noncompete`(경업금지), `tenure`(계속근무), `vesting`(베스팅·클리프), `lockup`(처분 제한)

### 3-3. `percent` — 비율

슬라이더 + 숫자 입력. 슬라이더 눈금에 숫자만 두지 않고 **의미 라벨**을 붙인다(예: `50% 과반` / `67% 3분의 2` / `100% 전원`). 비율 하나가 무슨 뜻인지 창업자가 알기 어렵기 때문이다. 라벨은 그 숫자가 무엇을 가리키는지만 말하고, 어느 값이 낫다고 말하지 않는다.

```
┌────────────────────────────────────────┐
│   [ 67 ] %                             │
│   ├────────────●─────────────┤          │
│   50%        67%           100%        │
│   과반      3분의 2          전원         │
└────────────────────────────────────────┘
```

- 사용처: `dragAlong`(발동 지분율), `penalty`(처분 금액 대비 비율)

### 3-4. `choice` — 단일 선택 카드

옵션 카드 그리드. 각 카드는 라벨 + 1줄 설명. `variant: "person"`이면 팀원 아바타 + 이름 + 역할로 렌더한다(별도 템플릿을 만들지 않고 variant로 처리).

- 사용처: `deadlock`(최종 결정권자, `person`), `shareType`(주식 종류), `buybackPrice`(퇴사 시 매수 가격), `vesting`(적용 여부)

### 3-5. `matrix` — 멤버별 행 입력

팀원 수만큼 행이 생기고 각 행에 입력한다. 두 가지 변형:

- `variant: "text"` — 역할 서술. 칩(대표이사/제품 총괄/개발 총괄/영업·마케팅/재무·운영/디자인) 클릭으로 채우고 자유 편집 가능
- `variant: "allocation"` — 지분율. **합계 100% 실시간 검증**. 합계가 100이 아니면 하단에 잔여/초과 표시하고 다음 버튼 비활성화

```
┌─────────────────────────────────────────────┐
│ 김민준 (나)   [대표이사] [제품 총괄] [개발 총괄]│
│              [ 제품 총괄 및 투자 유치      ]   │
│ 이서연        [ 백엔드 개발 및 인프라 운영  ]   │
│ 박도윤        [ 디자인 및 프론트엔드       ]   │
└─────────────────────────────────────────────┘

┌─────────────────────────────────────────────┐
│ 김민준 (나)     [ 50 ] %   ████████████       │
│ 이서연          [ 30 ] %   ███████            │
│ 박도윤          [ 20 ] %   █████              │
│ ─────────────────────────────────────────    │
│ 합계 100%  ✓                                 │
└─────────────────────────────────────────────┘
```

- 사용처: `roles`(역할·업무분담, `text`), `equity`(지분율, `allocation`)

### 3-6. `fields` — 사실정보 폼

라벨-값 쌍 나열. 합의 대상이 아니므로 미리보기는 있지만 갭 비교 대상이 아님을 화면에 명시한다.

- 사용처: `identity`(당사자 신원)

### 3-7. `composite` — 조합

위 템플릿 2개를 한 화면에 세로로 배치하고, 두 값에서 파생되는 결과를 하단에 자동 표시한다.

- `deadlock` = `duration`(협의 기간) + `choice/person`(최종 결정권자)
- `vesting` = `choice`(적용 여부) + `duration` × 2(베스팅 기간 / 클리프 기간). 적용 안 함을 고르면 하위 입력을 숨긴다
- `penalty` = `amount`(기준금액) + `percent`(비율) → 8조 ①②③⑤ 4개 빈칸 자동 채움

## 4. 질문 13개 — 조문 순서

계약서 조문 순서대로 배치한다. 미리보기가 계약서 흐름과 같은 순서로 나타나 사용자가 문서를 조립하는 감각을 갖는다.

`✓` = 확정 문항(사용자 지정 8개) · `제안` = 추가 후보(배지 표시, 5개)

| # | 배지 | 질문 | 조문 | 템플릿 | 비고 |
|---|---|---|---|---|---|
| 1 | 제안 | 당사자 신원 (이름·주민등록번호·주소) | 전문·서명란 | `fields` | 본인 것만 입력. 합의 대상 아님 |
| 2 | 제안 | 주식의 종류 | 전문·3의3조 | `choice` | 보통주식 / 종류주식 |
| 3 | ✓ | 얼마를 넘는 투자부터 전원 합의가 필요한가 | 2조①7호 | `amount` | — |
| 4 | ✓ | 합의가 안 되면 며칠 협의하고, 누가 결정하는가 | 2조③ 신설 | `composite` | duration + choice/person |
| 5 | ✓ | 각자 무엇을 맡는가 | 3의2조 | `matrix/text` | — |
| 6 | ✓ | 지분을 어떻게 나누는가 | 전문·3의3조 | `matrix/allocation` | 합계 100% 미달 시 진행 차단 |
| 7 | 제안 | 퇴사 후 몇 년간 경업을 금지하는가 | 4조② | `duration` | 베이스 1년 |
| 8 | ✓ | 최소 몇 년 근무 의무를 지는가 | 5조① | `duration` | **정합성 경고 대상** |
| 9 | 제안 | 베스팅·클리프를 적용하는가 | 5조 강화 | `composite` | 미적용 선택 시 하위 입력 접힘 |
| 10 | 제안 | 퇴사 시 주식을 얼마에 되사는가 | 5조②·9조③ | `choice` | 액면가 일괄 / 귀책 차등 |
| 11 | ✓ | 몇 년간 주식을 팔 수 없는가 | 6조 | `duration` | 베이스 5년 |
| 12 | ✓ | 몇 % 이상이면 전원 강제 매각인가 | 7의2조① | `percent` | — |
| 13 | ✓ | 계약을 어기면 얼마를 무는가 | 8조 | `composite` | amount + percent → 8조 4개 항 파생 |

제외한 2개: **회사명·체결일·부수**(전문·말미), **관할법원**(16조②). 서비스에 들어오기 전에 이미 정해진 값으로 본다.

### 4-1. 조문 간 정합성 경고 (`tenure`)

베이스 5조②는 "3년 이내에 퇴사하는 경우" 액면가 매수권을 규정한다. 5조①의 계속근무 의무 기간을 3년 미만으로 입력하면 두 항이 어긋난다.

- 트리거: `tenure` 입력값 < 3년
- 표시: 입력 필드 아래 경고(에러 아님) — "5조②는 3년 기준으로 작성되어 있습니다. 3년 미만으로 정하면 두 항의 기준이 달라집니다."
- 차단하지 않음. 사용자가 의도적으로 다르게 정할 수 있다.

유일한 조건부 로직이다. 나머지 12개 문항은 입력과 표시만 한다.

## 5. 화면 골격 (13문항 공통)

3컬럼이다. 왼쪽이 어디쯤 왔는지, 가운데가 무엇을 답하는지, 오른쪽이 무엇을 알아야 하는지를 각각 맡는다.

```
┌─ TopNav ─────────────────────────────────────────────────────────────┐
├────────┬──────────────────────────────────────┬──────────────────────┤
│ 사이드바 │ ┌ 질문 카드 (glass, radius 40) ────┐ │ 알아두면 좋은 것       │
│        │ │ ▬ 제2조 ③ · DEADLOCK      [제안] │ │ ┌──────────────────┐ │
│계약 기본│ │                                  │ │ │📘 이 조항은 무엇인가│ │
│의사결정●│ │ 합의가 안 되면 며칠 협의하고,      │ │ │  전원 합의라 한 명이│ │
│역할·지분│ │ 누가 결정하나요?                  │ │ │  반대하면 성립 안…  │ │
│근무·이탈│ │ 협의 기간이 지나도 합의가 안 될…   │ │ └──────────────────┘ │
│처분·제재│ │ ──────────────────────────────  │ │ ┌──────────────────┐ │
│        │ │  [ 입력 영역 — 템플릿별 ]         │ │ │🤝 정하지 않으면    │ │
│        │ │ ──────────────────────────────  │ │ │  전원 합의될 때까지 │ │
│        │ │ 📄 계약서 반영 미리보기            │ │ └──────────────────┘ │
│        │ │  "…주주들은 「7일」간 성실히       │ │ ┌──────────────────┐ │
│        │ │   협의한다. …해당 사항은          │ │ │⚖️ 한쪽으로 정하면  │ │
│        │ │   「김민준」의 의사에 따라…"       │ │ │ [낮게] … [높게] …  │ │
│        │ └──────────────────────────────────┘ │ └──────────────────┘ │
│        │                                      │ 법률 자문이 아닙니다   │
├────────┴──────────────────────────────────────┴──────────────────────┤
│ [← 이전]            4 / 13 ▓▓▓░░░░░  팀 2/3 응답            [다음 →]  │
└──────────────────────────────────────────────────────────────────────┘
```

폭은 사이드바 272px, 정보 칼럼 340px, 가운데가 나머지(카드 최대 880px)를 쓴다. 정보 칼럼은 `position: sticky`로 스크롤을 따라온다.

1320px 이하에서는 정보 칼럼이 질문 카드 **아래로** 내려가 카드 3장이 가로로 늘어선다. 좌우로 좁히지 않는 이유는 13px 본문이 240px 아래로 줄면 줄바꿈이 과해져 읽히지 않기 때문이다. 1100px 이하에서는 사이드바도 숨는다.

### 5-1. 계약서 반영 미리보기

이 목업의 핵심 차별점이다. 입력값이 **실제 조문 안에 하이라이트되어** 즉시 나타난다. 사용자는 자기 답이 계약서 어디로 가는지 그 자리에서 본다.

한 줄만 보여주지 않는다. **그 답이 들어가는 조문 전체**를 흰 지면 위에 계약서 그대로 그린다. 앞뒤 항이 함께 보여야 자기 값이 어떤 맥락에 놓이는지 판단할 수 있다.

블록 구조로 저장하고 렌더한다. 마크다운 문자열을 그대로 뿌리면 표가 `| 이름 | 종류 |` 형태로 노출되어 문서로 읽히지 않는다.

| 블록 | 렌더 |
|---|---|
| `para` | 조문 본문 단락. `indent`면 호(號) 목록으로 들여쓴다 |
| `table` | 실제 `<table>`. 테두리와 헤더 음영이 있는 계약서 표 |
| `sign` | 서명란처럼 줄바꿈·공백을 보존하는 좌측 정렬 줄 |
| `ellipsis` | `⋯ 이하 생략 ⋯` — 지금 문항과 무관한 항을 접는다 |

- 조문 원문은 「최종 계약서 샘플.md」에서 그대로 가져온다
- 입력 전에는 그 자리가 밑줄 빈칸으로 표시된다
- 입력 후에는 indigo 배경 + bold로 치환된다
- `penalty`는 입력 2개에서 파생된 4개 값이 제8조 전체(①~⑤) 안에서 채워진다
- 한글은 `justify` + `word-break: keep-all` 조합에서 어절 사이가 크게 벌어져 좌측 정렬을 쓴다

### 5-2. 정보 카드 칼럼

오른쪽 칼럼에 카드 3장을 세로로 쌓는다. 접지 않고 항상 펼쳐 둔다 — 답을 정하는 동안 읽어야 할 내용이라 클릭을 한 번 더 요구할 이유가 없다.

| 카드 | 아이콘 | 내용 |
|---|---|---|
| 이 조항은 무엇인가 | `BookOpen` | 조항의 구조와 작동 방식. 관련 법 조문이 있으면 함께 인용 |
| 정하지 않으면 | `HelpingHand` | 비워두면 어떤 기본 규칙이 적용되는지. 답할 동기를 만든다 |
| 한쪽으로 정하면 | `Scale` | `낮게 / 좁게`와 `높게 / 넓게` 두 태그로 양방향 결과를 대칭 서술 |

세 번째 카드는 값에 방향성이 있는 문항에만 나온다. 신원·주식종류·역할처럼 크고 작음이 없는 문항은 앞의 두 장만 표시한다.

칼럼 맨 아래에 면책 문구를 상시 노출한다. §2-1의 필수 요건이다.

> 일반적인 법률 정보이며 특정 사안에 대한 법률 자문이 아닙니다. 구체적인 판단이 필요하면 변호사와 상담하세요.

어느 카드에도 권고가 들어가지 않는다. 예를 들어 위약벌 문항의 `높게 / 넓게` 카드는 "민법 제398조 ②항은 손해배상예정액이 부당히 과다하면 법원이 적당히 감액할 수 있다고 정합니다"라고 적는다. "너무 높게 잡지 마세요"라고 적지 않는다.

### 5-3. 사이드바 — 그룹 5개 + 질문 13개

`app/mockup/questions/page.tsx`의 `qm-sidebar` 형태를 따르되, 그룹 아래에 그 그룹의 질문을 모두 펼쳐 둔다. 이전/다음 버튼만으로는 8번 문항에서 3번으로 돌아가는 데 다섯 번을 눌러야 한다.

- 그룹 헤더를 누르면 그 그룹의 첫 문항으로 이동
- 질문 항목을 누르면 그 문항으로 바로 이동
- 답한 문항은 초록 체크, 아직인 문항은 번호를 원 안에 표시
- 현재 문항은 배경 강조 + `aria-current="step"`
- 지분 합계가 100%가 아니어도 사이드바 이동은 막지 않는다. 「다음」 버튼만 잠근다 — 다른 문항을 보러 갔다 돌아올 수 있어야 한다

| 그룹 | 영문 | 문항 |
|---|---|---|
| 계약 기본 | Contract Basics | 1, 2, 3 |
| 의사결정 | Decision & Deadlock | 4, 5 |
| 역할·지분 | Roles & Equity | 6, 7 |
| 근무·이탈 | Tenure & Exit | 8, 9, 10, 11 |
| 처분·제재 | Transfer & Penalty | 12, 13, 14, 15 |

각 그룹에 완료 개수(`2/3`)를 표시하고, 현재 그룹은 좌측 indigo 바로 강조한다.

### 5-4. `제안` 배지

확정 문항이 아닌 5개 문항에 표시한다. 개발 중 구분이 목적이므로 눈에 띄되 방해하지 않아야 한다.

- 위치: eyebrow 행의 조문 태그 오른쪽
- 스타일: amber 계열 점선 테두리 pill, 텍스트 `제안`
- 사이드바 항목에도 동일 색 점 하나를 붙여 목록에서도 식별 가능
- 색만으로 구분하지 않는다 (`color-not-only`) — 텍스트 `제안`을 항상 포함

## 6. 데이터 구조

질문은 배열 하나로 선언한다. 위저드는 이 배열을 순회할 뿐이므로 문항 추가·삭제·순서 변경이 배열 편집으로 끝난다.

```ts
type QuestionTemplate =
  | { type: "amount"; presets: { label: string; value: number }[] }
  | { type: "duration"; unit: "일" | "개월" | "년"; presets: number[]; baseValue?: number }
  | { type: "percent"; marks: { value: number; label: string }[] }
  | { type: "choice"; variant?: "person"; options: { id: string; label: string; desc: string }[] }
  | { type: "matrix"; variant: "text" | "allocation"; chips?: string[] }
  | { type: "fields"; fields: { key: string; label: string; placeholder: string; kind?: "text" | "date" | "number" }[] }
  | { type: "composite"; parts: { key: string; label: string; template: QuestionTemplate }[] };

type QuestionInfo = {
  what: string;      // 이 조항이 무엇이고 어떻게 작동하는가
  ifUnset: string;   // 정하지 않고 두면 어떤 규칙이 적용되는가
  low?: string;      // 값을 낮게 정하면 생기는 일
  high?: string;     // 값을 높게 정하면 생기는 일
};

type ContractQuestion = {
  id: string;
  group: string;            // 사이드바 그룹
  article: string;          // "제2조 ③"
  articleTag: string;       // "DEADLOCK"
  proposed: boolean;        // true면 `제안` 배지
  consensus: boolean;       // false면 합의 대상 아님(사실정보)
  title: string;            // 질문 문장
  desc: string;             // 왜 정해야 하는지
  template: QuestionTemplate;
  preview: string[];        // 조문 원문. 치환 자리는 {0} {1}
  info: QuestionInfo;       // 정보 카드 3장의 내용
};
```

`preview`의 `{0}`, `{1}`이 입력값으로 치환되는 자리다. 위약벌처럼 파생값이 여러 조항에 들어가면 배열에 줄을 여러 개 둔다.

어느 템플릿에도 `defaultValue`가 없다. 값을 미리 채우면 그 값이 권고로 읽히고, 블라인드 답변인데도 팀원 전체가 같은 값에 앵커링된다. §2-1에서 금지한 것과 같은 문제다.

## 11. 검증

목업이지만 두 곳에 실제 로직이 있으므로 확인 수단을 남긴다.

1. **지분율 합계 검증** — 합이 100이 아니면 다음 버튼 비활성 + 잔여량 표시
2. **`tenure` 정합성 경고** — 3년 미만 입력 시 경고 노출, 차단은 안 함
3. **금지어 검사** — 사용자 노출 문자열에 `권장`·`추천`·`통상`·`업계 평균` 등이 들어가면 실패(§2-1)

두 함수를 순수 함수로 분리하고 `lib/contractQuestions.test.ts`에 assert 기반 자체 점검을 둔다. 프레임워크 없이 기존 `lib/annexClauses.test.ts` 관례를 따른다.

나머지는 렌더링과 상태 전환뿐이므로 별도 테스트를 두지 않는다.

## 13. 열린 질문

`제안` 배지가 붙은 5개 문항(신원·주식종류·경업금지·베스팅·매수가격)은 목업 검토 후 확정하거나 제거한다. 제거는 `CONTRACT_QUESTIONS` 배열에서 항목을 지우는 것으로 끝난다 — 사이드바 개수와 진행률은 배열 길이에서 계산한다.
